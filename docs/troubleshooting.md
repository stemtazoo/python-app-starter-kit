# エラーが出たときの進め方

この文書は、プログラム初心者がエラーを見て止まってしまったときに、原因を一人で考え続けず、AIへ状況を正確に伝えるための手順です。

## 最初にすること

> エラーが出たら、すぐにコードを何度も変更せず、まずエラー画面のスクリーンショットを撮ります。

エラーメッセージには、問題が起きたファイル、場所、原因の手掛かりが含まれています。コード全体を先に見直すより、最初にエラー画面をそのまま記録した方が、どこから確認すればよいか判断しやすくなります。

## 基本の5ステップ

1. **いったん止める**  
   エラーが出た状態で、思いついた変更を続けて加えません。

2. **エラー画面を撮る**  
   エラーの先頭から最後まで、できるだけ読める大きさでスクリーンショットを撮ります。

3. **秘密情報を確認する**  
   パスワード、APIキー、氏名、メールアドレス、社内URL、顧客情報などが映っていないか確認し、必要な部分を隠します。

4. **直前の操作を一言添える**  
   何をしたときにエラーが出たかをAIへ伝えます。

5. **AIからの確認を1つずつ試す**  
   複数の修正を同時に行わず、1つ変更したら同じ操作で結果を確認します。

## AIへ伝える内容

最初は、次の3点があれば十分です。

```text
1. エラー画面のスクリーンショット
2. エラーが出る直前に行った操作
3. 本来どうなると思っていたか
```

例えば、次のように伝えます。

```text
start.batをダブルクリックしたところ、添付画像のエラーが出ました。
本来はアプリの画面が開く想定です。
```

この段階で、コード全体を貼り付ける必要はありません。AIがエラー画面を確認した後、必要なファイルやコードの範囲を案内します。

## スクリーンショットの撮り方

### Windows

次のいずれかを使います。

- `Windows + Shift + S`：必要な範囲を選んで撮影
- `Alt + Print Screen`：現在のウィンドウを撮影
- Snipping Tool：範囲を選んで保存

コマンド画面がすぐ閉じる場合は、`start.bat`のエラー処理に `pause`を入れ、画面が残るようにします。

## 撮影するときのポイント

- エラーの最後の行だけでなく、その少し前から撮る
- ウィンドウのタイトルや実行したコマンドも、可能なら含める
- 文字が小さい場合は、ウィンドウを広げて撮り直す
- 縦に長いエラーは、つながりが分かるよう複数枚に分ける
- 関係のないデスクトップや別アプリは写さない
- 黒塗りや切り抜き後に、秘密情報が残っていないか再確認する

詳しい注意は[チャット・データ取り扱いガイド](security-and-privacy.md)を確認してください。

## スクリーンショットだけでは足りない場合

長いエラーログ、検索可能な文字列、正確なファイル名などは、後からテキストでも必要になることがあります。

その場合はAIが、次のように必要な範囲を指定します。

```text
エラーの「Traceback」から最後の行までを、テキストとして貼り付けてください。
氏名、パス、URL、認証情報は架空の値へ置き換えてください。
```

最初から大量のログやコードを送るのではなく、エラー画面から必要な範囲を絞ります。

## AIが行うこと

スクリーンショットを受け取ったAIは、次の順番で支援します。

1. 画像から読み取れるエラーを短く説明する
2. 最初に確認することを1つ示す
3. 追加情報が必要なら、ファイル名や範囲を具体的に指定する
4. 修正箇所と貼り付け方法を具体的に示す
5. 元の操作をもう一度行い、解決したか確認する

原因候補を大量に並べたり、最初からコード全体の書き直しを求めたりしません。

## 解決後に残す記録

同じ問題が起きそうな場合は、READMEやトラブルシューティングへ次を短く残します。

- 表示されたエラー
- 原因
- 解決方法
- 再発時の確認方法

一時的な入力ミスなど、再利用する可能性が低い内容は無理に記録しません。
