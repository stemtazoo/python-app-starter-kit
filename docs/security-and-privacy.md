# チャット・データ取り扱いガイド

この文書は、AIと一緒にアプリを制作するときに、パスワードや個人情報などを誤ってチャットやGitHubへ共有しないための基本ルールです。

## 最初に覚えておくこと

> パスワード、秘密のキー、個人情報、実際の業務データは、AIとのチャットへ入力しないでください。

コードの相談に、本物の値は必要ありません。名前や値を架空のものへ置き換えても、ほとんどの相談は進められます。

会社で利用する場合は、この文書よりも勤務先の情報セキュリティ規程を優先してください。入力してよいか判断できない情報は、共有する前に社内の担当者へ確認します。

## チャットへ入力しない情報

### 認証に使う情報

- パスワード、暗証番号
- ワンタイムパスワード、認証コード
- APIキー、アクセストークン
- Cookie、セッションID
- 秘密鍵、回復コード
- データベースの接続文字列
- パスワードを含む設定ファイル

### 個人を特定できる情報

- 氏名、住所、電話番号、個人のメールアドレス
- 生年月日、顔写真
- 社員番号、顧客番号
- マイナンバーなどの公的な識別番号
- 口座、カード、給与などの金融情報
- 健康、医療、人事評価などの情報

### 会社や顧客の秘密情報

- 顧客データ、取引情報
- 社外秘の図面、仕様書、契約書
- 公開されていない製品情報
- 社内システムのURL、サーバー名、ネットワーク構成
- 実際の業務ファイルやデータベース
- 機密情報が含まれるエラーログ

## 安全な置き換え方

本物の値の代わりに、意味が分かる架空の値を使います。

| 本物の情報 | チャットで使う例 |
|---|---|
| 実際のパスワード | `YOUR_PASSWORD` |
| APIキー | `YOUR_API_KEY` |
| 氏名 | `山田太郎`、`USER_A` |
| メールアドレス | `user@example.com` |
| 社員番号 | `EMP001` |
| 社内サーバー | `myhost.example.com` |
| 実際のフォルダ | `C:\path\to\input` |
| 顧客名 | `顧客A` |
| 製品番号 | `PRODUCT-001` |

APIキーらしい形を途中まで残す必要もありません。`sk-xxxx`のように実際の先頭部分を見せず、`YOUR_API_KEY`へ完全に置き換えます。

## ファイル・画像・ログを共有する前の確認

ファイルを添付したり、画面を撮影したり、エラーを貼り付けたりする前に、次を確認します。

- 氏名やメールアドレスが映っていないか
- タイトルバーやファイルパスに利用者名がないか
- URLにセッションIDや顧客番号が含まれていないか
- ログにAPIキー、Cookie、入力データが出力されていないか
- Excelの別シートや非表示列に個人情報がないか
- 画像の背景に別のアプリや通知が映っていないか
- ファイルのプロパティやメタデータに作成者情報がないか

必要な部分だけを切り出し、値を伏せるか架空データへ置き換えてから共有します。

## AIへ相談するときの安全な例

### 設定ファイル

```yaml
server: myhost.example.com
user: USER_NAME
password: YOUR_PASSWORD
```

### 表データ

```text
社員番号,部門,作業時間
EMP001,部門A,2.5
EMP002,部門B,3.0
```

### ファイルパス

```text
C:\path\to\input\sample.xlsx
```

列名なども機密に当たる場合は、`項目A`、`項目B`のように置き換えます。

## アプリ内での保存方法

パスワードやAPIキーをコードへ直接書きません。

- 秘密情報は環境変数、OSの資格情報管理機能、または承認された秘密管理方法を使う
- 利用者固有の設定ファイルを使う場合は、`.gitignore`へ追加する
- GitHubへ登録する設定例には、架空の値だけを記載する
- ログへパスワード、APIキー、個人情報を出力しない
- サンプルデータには実データを加工したものではなく、原則として最初から作った架空データを使う

OpenAIの公式資料でも、APIキーをコードや公開リポジトリへ露出させず、環境変数や秘密管理サービスで扱うことが推奨されています。

## 誤って入力・公開した場合

パスワード、APIキー、トークンなどを誤って共有した場合は、削除だけで終わらせません。

1. 該当するパスワードやキーを無効化する
2. 新しい値へ変更する
3. GitHub、ログ、共有ファイルなど、ほかの場所にも残っていないか確認する
4. 業務情報の場合は、勤務先のルールに従って担当者へ連絡する

OpenAIの公式資料でも、APIキーが漏えいした可能性がある場合は、速やかに無効化して新しいキーへ交換するよう案内されています。
